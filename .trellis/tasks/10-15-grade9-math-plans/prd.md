# PRD：九上数学 211 篇推文计划批量入排程

## 背景

- 用户给出 `docs/img/` 下 6 张九年级上册课程大纲照片（37 讲、174 个板块）。
- 目标：按大纲为两个公众号账号生成**每日 1 篇**的推文计划，写入 250 控制台（DB 为真源），由现有调度器每天自动生成 + 发布 + 邮件推送。
- 账号（250 `/root/wechat-flow`，console.db 已确认）：
  - `second` = 巧思初数（cdp 9222，enabled）
  - `gaoh` = gaoh的技术分享（cdp 9223，enabled）
  - 当前两账号 W42（本周）计划为 10-12~10-18 八年级内容。按用户决定：**W42 整周直接用新计划覆盖**（不保留旧 4 天），新计划 211 天从 **2026-10-16（周五）** 起连续日更，至 2027-05-14（W42 末 3 天 + W43~W72 共 31 周）。已发布文章不受影响，仅计划表内容替换。

## 需求

### R1 推文计划生成（核心）

规则：每讲的每个板块生成 1 篇推文；每讲结束后再生成 1 篇该讲知识点汇总推文。
即 每讲推文数 = 板块数 + 1。

- 大纲共 **37 讲 / 174 板块 → 211 天推文**（明细见附录 A，已逐图核对）。
- 每天 1 篇、7 天/周连续排期，从 2026-10-16（W42 周五）起，211 天 = 31 周（至 2027-05-14，W42 末3天 + W43~W72 完整 30 周）。
- 每条计划项字段沿用现有 schema（`PlanDay`）：`date / weekday / module / topic / grade=九年级 / difficulty / angle / titleSuggestion / outline[]`，额外加 `lecture`（第几讲）、`board`（板块名）、`isSummary`（是否汇总篇）便于追溯。
- **同一主题写入两个账号**：second 与 gaoh 各 211 条，主题相同；通过 `angle`/`titleSuggestion` 体现账号定位差异（巧思初数=初中数学教学视角；gaoh的技术分享=偏技术/学习方法视角）。
- 内容要求（写进 outline/angle，供生成文章的 agent 遵循）：内容足够丰富、少说废话；**结合该知识点检索历年中考真题**，拆解真题对应的知识点进行讲解。

### R2 写入控制台 plans 表

- 走控制台 API `PUT /api/accounts/:id/plans`（`period_type=week`，每周一文件），DB 落库后自动物化回 `data/<alias>/plans/<week>.json`，调度器每日 07:30 检查发布。
- **W42 特例**：upsert 整周覆盖为仅含 10-16/17/18 三天的新计划（第1讲前3篇），旧 4 天计划条目随之移除（已发布文章记录不动）。
- 写入后校验：`plans` 表行数、物化文件天数、跨周无断档/无重叠。

### R3 邮件推送（每次发布）

- 每篇发布成功后邮件同时发往 **2199382542@qq.com**（gaoh的技术分享）与 **1653491523@qq.com**（巧思初数）。
- 现状：250 `config.json` 两账号 `emailTo` 均为空，且 `notify.email.enabled=true/on=publish`。需要：
  1. 给两账号配置 `emailTo`（含上述两邮箱，或按账号区分+互抄，最终按用户确认）；
  2. 邮件正文附**相应账号的账号名与密码**（用户明确要求"避免上服务器找密码"）→ 需在邮件模板中注入控制台登录信息（控制台用户/密码 或 公众号账号别名+CDP 信息，具体注入什么凭据在 design 中定，须经用户确认）。

### R4 manim + ffmpeg 动画 gif（条件插入）

- 若某板块知识点适合动画演示（二次函数图象变换、旋转、圆的性质等），生成文章时插入 manim 制作、ffmpeg 转 gif 的动画。
- 现状约束：**250 上有 ffmpeg 7.0.2，无 manim**；`config.json` `manim.enabled=true`，引擎 `publisher.ts` 已支持"manim scene.py → scene.gif"预处理（agent 写文章时产出 scene.py，引擎渲染）。
- 决策点（design 定）：250 安装 manim（pip，需 latex 依赖较大）；或先在计划 topic/outline 中标注"【manim】"建议场景，安装后自然生效；或生成在开发机渲染后同步。默认方案：在 250 安装 manim 并在适用板块的计划项中加 `manimHint` 字段。

### R5 ffmpeg 封面

- 现状：封面由 `src/cover.ts` 用 **ImageMagick convert** 生成 900x500 模板封面。
- 需求：改为/补充**按知识点用 ffmpeg 生成相应封面**（如：深色底 + 知识点标题 + 数学元素；可用 ffmpeg drawtext/overlay 实现，ffmpeg 250 已有）。
- 实现归属引擎层小改（design 定：替换 convert 调用为 ffmpeg，或 cover.mode 增加 `ffmpeg` 选项）。

### R6 验收标准

- AC1：console.db 中 second、gaoh 的 W42（3 天：10-16~10-18）及 W43~W72（各 7 天）计划合计 days 各 211 条，日期 2026-10-16 ~ 2027-05-14 连续无断档。
- AC2：物化文件 `data/{second,gaoh}/plans/2026-W*.json` 与 DB 一致。
- AC3：两账号 `emailTo` 配置生效，发布后邮件送达两邮箱且含账号密码信息（先用一篇 dryrun/测试邮件验证）。
- AC4：封面生成走 ffmpeg 路径，`bun build` + `tsc` 通过，250 同步后封面探针 OK。
- AC5：manim 方案落地（安装完成或 graceful 降级：无 manim 时跳过 gif 不阻塞发布）。
- AC6：首日（10-16）由调度器真实跑通一篇端到端（生成→发布→邮件）。

## 非目标

- 不修改已发布的文章与草稿记录（W42 旧计划条目整体被覆盖属预期行为）。
- 不重写调度器/发布链路（除封面 ffmpeg 小改）。
- 不保证 211 篇逐篇人工审阅——抽查 W43 首周 + 汇总篇样本。
