# PRD — AI 封面：按推文语义生成 900×383 公众号封面

## 1. 背景

当前封面是纯确定性的「渐变底色 + 标题文字」（`generateFfmpegCover` / `generateTemplateCover`），
和文章内容无关：任何一篇数学推文的封面看起来几乎一样，读者在订阅号列表里无法靠封面辨识。

已实测确认（2026-10-19，250 真机）：

- meta-gateway 的 `POST /v1/images/generations` 可用，**复用已有网关 key，无需新增凭据、无需新增 npm 依赖**；
- 实际可用的图像生成模型只有两个（网关**裸 id**）：
  - `cn:hunyuan-image-alpha-edit`（腾讯混元，15–21s）✅
  - `global:gpt-image-2.5-sunburst`（GPT Image 2.5，~35s）✅
- `workbuddy/cn` 分组下**唯一**可出图的是 `workbuddy/cn:hunyuan-image-alpha-edit`；
  `glm-4.6v` / `glm-5v-turbo` / `hunyuan-2.0-instruct` 是视觉**理解**模型，走 images/generations 一律 503；
- 主模型 `workbuddy/cn:deepseek-v4.1-flash` **不支持图片生成**（503 `No available channel`），它只负责写文案。

## 2. 目标

让封面**从文章内容来**：AI 读标题 + 正文，先产出一份结构化「封面简报」（主体意象、配色、氛围），
再由图像模型画出来，最后确定性后处理成公众号标准 **900×383（2.35:1 头条大图）**。

三个硬指标：

1. **封面必须能从视觉上区分文章** —— 同一账号连续 5 天的封面，主体意象与主色不应重复。
2. **绝不阻断发布** —— 图像模型挂了/超时/返回不可用，自动降级到现有渐变封面。
3. **确定性兜底优先于华丽** —— AI 只产出「画什么」和「什么颜色」，尺寸/裁切/落盘路径全部由代码决定。

## 3. 需求（来自用户确认）

| # | 决策 | 说明 |
|---|---|---|
| D1 | 尺寸 **900×383** | 公众号 2.35:1 头条大图标准。**所有封面模式统一**（含降级链），不再是 900×500 |
| D2 | 配色**由文章内容决定** | 不写死账号色板；AI 从正文语义提取主色，账号色板只作为兜底/风格锚 |
| D3 | **每篇 1 张** | 不生成多个候选、不做 A/B；只当封面用 |
| D4 | 保留「渐变+纯文字」兜底 | AI 出图失败 → 现有 `generateFfmpegCover`（失败再 `generateTemplateCover`） |

## 4. 非目标（明确不做）

- 不做封面 A/B 测试与多候选挑选；
- 不改 `setDraftCover()`（O-B 已真机验收，只消费 `cover.png` 这个约定路径）；
- 不让 AI 在图上画中文标题（AI 写中文字必出错，标题由微信/后处理负责）；
- 不引入 l0veyou / Playwright 截图方案（API 直连已可用且零依赖）；
- 不动文章生成、公式 SVG、manim 动图链路。

## 5. 用户故事

- **作为读者**，我在订阅号列表看到封面就知道今天讲什么（抛物线相切 / 根与系数 / 判别式…），而不是一排同样的蓝底白字。
- **作为运营者（gaoh）**，我希望某天出图失败时文章照样准时进草稿箱，只是封面回落成渐变图，并在日志/邮件里看到降级原因。
- **作为维护者**，我希望封面能单独重跑（`cover --ai`）而不重跑整篇文章，且失败原因一眼可见。

## 6. 验收标准（可验证）

| ID | 验收项 | 验证方式 |
|---|---|---|
| AC1 | 尺寸精确 900×383 | `identify`/`ffprobe` 读生成文件，断言 `900x383` |
| AC2 | 封面随内容变化 | 同账号连续 3 个不同 topic 生成封面，主体意象/主色不同（人工看图 + 简报 JSON 对比） |
| AC3 | 简报是结构化且可审计 | 落盘 `imgs/<date>/cover-brief.json`，含 `subject/palette/motif` 等字段 |
| AC4 | 图像模型失败不阻断发布 | 用坏 model id + 坏 baseUrl 各跑一次，断言文章仍生成、封面回落渐变、日志有降级原因 |
| AC5 | 两个图像模型互为兜底 | 主模型置为不可用 id，断言自动换到 fallback 并成功出图 |
| AC6 | 幂等 | `--reuse` 且 `cover.png` 已存在时不重新出图（不烧 token/额度） |
| AC7 | 250 真机草稿封面 | 250 上出文后，草稿箱封面为 AI 图（`setDraftCover` 成功），非手动 |
| AC8 | doctor 能查出图像模型不可用 | `bun src/cli.ts doctor --all` 新增 `cover-model` 行 |
| AC9 | 回归 | `npx tsc --noEmit` 0 错；`tools/cover-selftest.ts` 全绿；250 `doctor --all` 全绿 |
| AC10 | 成本可控 | 每篇 ≤1 次摘要调用 + ≤2 次出图调用（主+1 fallback），有超时上限 |

## 7. 风险

| 风险 | 缓解 |
|---|---|
| 图像模型把中文画成乱码 | prompt 显式禁文字；`overlayTitle` 默认 false，标题不交给 AI |
| 出图慢拖垮发布窗口 | 单模型超时 120s，总预算 ≤ 300s，超时即降级 |
| 900×383 与既有 900×500 兜底不一致 | 全模式统一 900×383（含 ffmpeg/template），一次性对齐 |
| 200×200 小图中心裁切切掉主体 | prompt 要求主体居中、四周留白；后处理 center-crop |
| 网关换 key/baseUrl | 三级解析：配置 → env → pi `models.json`，任一可用即可 |
