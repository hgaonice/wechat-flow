# PRD（父任务）：运营韧性升级 —— 登录态滚动更新 + 图像模型普查 + 控制台前端重构

## 背景

用户在一次请求中提出三个互不相同但同属「日常运营韧性」的问题：

1. **每次代码调整都要重新扫码登录公众号** → 希望登录态长期保存、滚动更新，避免频繁扫码。
2. **控制台界面太丑** → 希望参考 `https://github.com/linux-do/cdk` 等优秀项目重做前端设计。
3. **希望有更好/免费的图像模型**（gpt-image-2.5 或更强）用于每日图文封面。

三者可独立验收、独立归档，故拆为父任务（需求集 + 任务地图 + 交叉验收）+ 3 个子任务。

## 用户已确认的决策

|---|---|---|
| O1 | 执行顺序 | **#1 登录态 → #3 图像模型 → #2 前端重构**（#1 影响每日发布，最高优先；#3 独立、纯调研可并行；#2 工作量最大，放最后分 4 步增量） |
| O2 | 任务结构 | 父任务 + 3 子任务（本结构） |

## 非目标

- 不做"永久免扫码"承诺：MP 登录票据由微信侧控制（实测硬上限 96h、需真实鉴权请求滑动续期）。目标定义为**服务器不中断运行则长期无需扫码**。
- 不在本父任务内做公众号改名（已由 `10-16-rename-gaoh-account` 承接）、不做内容策略调整。
- 不引入新的前端框架/构建链（除非 Q1 被用户改判）。
