## 这里放什么

| 文件 | 作用 |
|---|---|
| [`TEMPLATE.md`](./TEMPLATE.md) | 可直接复制的交接骨架，章节与 spec 的必要章节清单（H1–H10）逐项对应 |
| `YYYY-MM-DD-<用途>.md` | 已发出的交接稿归档（**只读历史，不再续写**） |

## 命名约定

```
YYYY-MM-DD-<用途>.md
```

- 日期 = **交接稿生成日**（不是任务完成日）
- `<用途>` = 目标的一句话短写，用连字符分隔，避免中文与空格，例如：
  - `2026-10-13-cnb-console.md` —— 在 CNB 完成控制台 C1–C6
  - `2026-11-02-gpu-host-media-pipeline.md` —— 在 GPU 机器上做媒体管线
- 一稿一目标：目标变化写新稿，**不要续写旧稿**

## 生命周期

```
TEMPLATE 复制 → 填空 → 归档到此目录并提交 → 执行中（状态：有效）
   → 目标达成 / 任务归档 / 被新稿取代 → 在文件头部补一行「状态：已失效（日期）—— 原因：…」
```

- **不要删除失效稿**：交接历史是复盘材料（"当时交接了什么、对方按哪版执行"）。
- 接手方开工前先比对**基线 commit SHA** 与当前 `HEAD`；不一致就先 `git log --oneline <sha>..HEAD` 看差异，判断本稿是否仍适用。
- 头部必写三件事：**生成时间、基线 commit SHA、失效条件**。

## 硬约束（摘要，详见 spec §3）

- **绝不**在本目录任何文件里写明文 token / API key / master key / DB 口令 / `config.json` 与 `.env` 的真实值。
- 需要凭据时写"向谁索取、去哪儿签发"，不写值本身。
- 稿中引用的每个路径都必须真实存在（写完用 `test -e` 逐条验一遍）。
